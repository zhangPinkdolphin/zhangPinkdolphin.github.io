ROUND 0

一句话点燃了目标

你说：

「L4 归档系统跑了一个半月了，积累了 266 个对话 session。但我发现 Agent 还是对我的过去一无所知——每次对话都像第一天认识。你能不能设计一套方法，从这些历史对话中提取出有价值的知识，让未来的我能'继承记忆'？不要写死脚本，要一套方法论，你自己来执行。」

没有明确的技术需求，没有指定输出格式。一个开放式的目标，加上时间预算——这正是 Goal Mode 最擅长的场景。

ROUND 1 — 探路

LLM 接到任务，开始分析

LLM 内部思考

目标：设计一套方法从 L4 历史中提取知识。

先搞清楚现状：
→ 读取 compress_session.py → 原来是把原始日志压缩成 session 格式，打包 zip，并生成了 all_histories.txt（[USER]/[Agent] 对话链）
→ 读取 all_histories.txt 前几个 session → 格式清晰，[USER] 消息保留完整
→ 问题：数据存好了，但没人读，Agent 不知道历史

我要设计一个 SOP。关键问题是：挖什么？

从用户的角度想，最有价值的信息类别：

• 用户做过什么项目？（活动/项目）
• 用户对什么满意/不满意？（情绪事件）
• 哪些事情已经结束了？（已消失事项）

再想：谁执行？
→ 脚本写规则？情绪太模糊，规则写不完善
→ LLM 执行？能理解语义和语气，准确率高
选后者。SOP 就是给 LLM 的方法论文档。

第一版草稿诞生了——定义了 情绪事件 持续活动 已消失事项 三个核心类别。

ROUND 2 — 补坑

重读草稿，发现三个问题

LLM 自我审视

重新读一遍自己写的草稿，发现几个致命问题……

问题一：情绪判断标准模糊。用户不说"我生气了"就不算情绪事件吗？反之，用户提到"崩溃"就一定是情绪事件？

💡 决策：情绪判断看语气不看内容——讨论负面话题但本人情绪稳定，不标记。

问题二：无法回溯原文。如果只记录结论不记 session 来源，将来有争议时怎么验证？

💡 决策：session 标识必须与 L4 zip 内文件名一致（如 0403_2013-0403_2145），无法定位回原日志的记录没有价值。

问题三：分类冲突。如果某个活动既高频出现又最近停止了——它属于「持续」还是「已消失」？

💡 决策：如果收集到矛盾信号（频次高 vs 已停止），必须做最终裁决再写入。且「持续」和「已消失」是两个独立分类，产物中必须明确分开。

ROUND 3 — 打磨

最后的润色

LLM 最终检查

再读一遍，问自己：这个 SOP 执行者看到后，能不能无歧义地执行？

• 数据源路径是否准确？✅
• 产物格式是否清晰？情绪事件 → 追加式（只增不删）；活动知识层 → 读取→更新→写回
• 增量标记是否说明？✅ 记录处理进度，避免重复劳动
• "活动归类是'用户在做什么'的知识表示，不是对话摘要"——这个区别很重要，要明确写出来。

BEHIND THE SCENES

Goal Mode 是怎么工作的？

你可能注意到了——整个创作过程没有我（人）一步步指挥，而是 Agent 自己迭代完成的。这就是 Goal Mode 的核心：

# goal_state.json { "objective": "设计一套方法让Agent能从历史中提取知识...", "budget_seconds": 7200, "status": "running", "max_turns": 30 }

设置好目标 + 时间预算 → Agent 被反复唤醒 → 每次醒来都检查进度、决定下一步 → 预算耗尽自动收口交付。

用户只说了 一句话需求，后续的判断、迭代、打磨全由 Agent 自行完成。
