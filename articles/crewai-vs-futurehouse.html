一、为什么把这两个放在一起？

CrewAI 和 FutureHouse 经常被并排讨论，因为它们在同一个大叙事里：「多智能体（Multi-Agent）」会成为 AI 的下一个应用形态。两者都让多个自主 AI 智能体分工协作，但如果你把「智能体」换成「员工」，区别立刻就清晰了——

一句话总结：CrewAI 是「怎么让多个 Agent 协作」的通用开发工具——像导演一样编排 AI 员工团队去完成任何自动化任务；FutureHouse 是「把整个科研流程自动化」的领域研究项目——目标是造出能自己提出假设、设计实验、分析数据、得出结论的 AI 科学家。

所以这不是「谁更好」的对比，而是两条不同路线的对比：一条做平台，一条做应用；一条面向所有行业，一条深耕生物学与药物研发；一条以「执行量」论英雄，一条以「发现数量与可复现性」论成败。

二、CrewAI：通用多智能体编排框架

2.1 它是什么

CrewAI 是一个开源的 Python 框架，2024 年 1 月由 João Moura 推出，从零构建、不依赖 LangChain。核心思路：为每个智能体定义Role（角色）、Goal（目标）、Tools（工具），让它们像人类团队一样分工协作。比如「研究员 → 作家 → 审核员」三智能体流水线自动产出市场分析报告。

它有两副面孔：底层是免费开源的编排框架，上层是面向企业的 Agent 平台（AMP / Crew Studio / Discovery）。官方口径的几组数据：

数据说明：2B 次执行与 63% 均为 CrewAI 官方自述（官网「Used by 63% of the Fortune 500」，第三方口径约 60%），建议当作「官方宣称」而非独立审计数据。

2.2 架构：Flows + Crews

CrewAI 的核心设计是双层架构，这也是它区别于其他框架最明显的地方：

Flows（流程）——确定性骨架。负责应用的整体结构：步骤顺序、状态管理、循环、条件分支、错误处理、人机协作节点。它是事件驱动的，且支持@persist()持久化、结构化/非结构化状态（Pydantic 模型 / 字典），甚至能导出为独立代码。

Crews（团队）——自主执行单元。由多个带角色、工具、记忆的智能体组成，负责 Flow 委派下来的「需要判断力」的任务。

设计哲学——把「可预测的流程控制」和「不可预测的推理任务」刻意分离：确定性部分交给 Flow，智能部分交给 Crew。官方认为，这是 2B 次执行中跑出成绩的团队共同特征。

此外还有面向生产的安全治理：guardrails（护栏）、human-in-the-loop（人在环）、层级 manager-worker 架构、任务级工具权限、可追踪的执行记录——这些是它主打企业市场的底气。

2.4 实践案例

DocuSign：销售管线加速（官方披露的明星案例）

用 5 个智能体（Identifier / Researcher / Composer / Validator + Orchestrator）嵌入一个确定性 Flow：识别线索 → 研究客户 → 撰写个性化触达 → 质量校验 → 发送（官方叫 3P：Productivity / Personalization / Pipeline）。

校验层有三道：LLM-as-judge 质量评审 + 对照源材料的幻觉检查 + 基于 API 的质量评分，出问题能精确定位是哪一层拦截的。结果是触达周转时间显著缩短、打开率/回复率/转化率提升；据官方称，相比此前图式（Graph）架构的实现，代码量减少约 14 倍。

AB InBev：每年 300 亿美元决策交给 AI

官方博客提到，AB InBev 每年约 $30B 的决策经由 AI 支持，目前在 CrewAI AMP 平台上已有数十个生产用例，带来数百万美元级别的财务影响。

某人力资源服务公司：「Andy」工单智能体

每月 3,000+ 员工工单，合规团队不堪重负。上线「Andy」后并不急着全自动——先是100% 人工审核（AI 起草回复、标注相关条款、标记边缘案例），跑了几千次后质量得到信任，逐步下放到 50%+ 无人审核。这是「信任阶梯」的教科书式案例。

更多客户与社区案例

  • 官方披露的客户/合作方：PepsiCo、Johnson & Johnson、PwC、美国国防部（DoD）、NTT Data、Experian、BDO 等
  • 开源社区：基于 CrewAI + Streamlit 的多智能体旅行规划助手（2026-02，GitHub）；三智能体邮件分诊 cookbook（Scalekit，2026-06：扫描 → 按优先级分类 → 起草回复）
  • 学术：IEEE 论文（2025-12）用 GPT-4-mini + CrewAI 实现客服工单多智能体自动化（数据摄入 → 工单分类 incident/request/change/problem → 生成解决方案）

小结：CrewAI 的实践案例高度集中在「流程自动化」——工单、销售、研究、内容生产。衡量标准是处理量、代码量、转化率这类业务指标。

2.5 需要留意的地方

① 2B 执行量、63% Fortune 500 都是官方口径，无独立审计；② 与 AutoGen/AG2、LangGraph 竞争激烈，官方博客多次「吐槽」图式架构（调试噩梦），本质是框架路线之争；③ 生态里大量真实生产案例发生在「有预算做治理」的大企业，中小团队更多停留在原型阶段。

三、FutureHouse / Edison Scientific：AI 科学家

3.1 它是什么 + 关键时间线

FutureHouse 是 2023 年在旧金山成立的非营利研究机构（501(c)(3)），创始人是物理学家/生物工程师 Sam Rodriques（TIME 100 AI 2025 入选者）和化学 AI 专家 Andrew White（ChemCrow、PaperQA 作者）。目标宏大：十年内构建出「AI 科学家」。项目早期就获得了前 Google CEO Eric Schmidt 等人的支持。

3.2 Robin：登上 Nature 的全自动科研系统

2026 年 5 月 19 日，FutureHouse 在 Nature 发表论文《A multi-agent system for automating scientific discovery》（s41586-026-10652-y），正式报道全球首个全自动科学发现闭环系统 Robin（2025 年 5 月曾以预印本形式发布）。论文正文中的全部假设、实验方向、数据分析与图表，均由 Robin 完成。

Crow（乌鸦）——快速扫描数百篇文献，抓取关键信息，确定实验策略与候选方案；

Falcon（猎鹰）——深度文献综述，生成全面报告，评估每一条候选策略；

Finch（雀鸟）——自主分析实验数据：流式细胞术、RNA-seq 都能自己写代码、画图、给出统计结论。

实战：挑战「视力杀手」dAMD

  • 定位机制：读数百篇眼科论文后提出——干性年龄相关黄斑变性（dAMD）的关键是视网膜色素上皮（RPE）细胞吞噬功能受损，代谢废物堆积毒害感光细胞；增强吞噬能力是突破口
  • 筛选老药：在药物库交叉比对，提名一批「老药新用」候选，人类科学家体外验证命中率不俗
  • 关键发现：Ripasudil（ROCK 抑制剂，原用于青光眼）与 KL001（隐花色素稳定剂，调控昼夜节律）均能显著增强 RPE 吞噬——后者为首次报道
  • 机制破译：面对 Y-27632（另一 ROCK 抑制剂）的实验数据，Robin 自主提议 RNA-seq 测序，发现药物通过重塑细胞骨架与调控自噬加速废物清理，并捕捉到被学界长期忽略的 ABCA1 基因显著上调——为 dAMD 新靶向疗法打开方向

3.3 Kosmos：新一代 AI 科学家

Kosmos 是 Edison Scientific 的商业旗舰（2025-11 上线），定位是「与研发团队协作的 AI 科学家」——它会在一次最长 12 小时的运行里完成相当于人类研究员约 6 个月的工作。

Kosmos 采用「结构化世界模型」，将数百个智能体的信息拧成一股绳，即便输入上千万 token 的文献也能专注核心研究问题；自主循环架构让它从「被动执行指令」变成「主动规划研究」。每条结论都可溯源到具体代码或原文，并输出下一步分析计划，供下一轮循环使用。

评估成绩（New Scientist 报道）

  • Edison 请至少博士级理解力的科学家评审 Kosmos 报告的 102 条陈述：79.4% 总体成立（数据分析类 85.5%、文献类 82.1%、原创综合结论 57.9%）
  • 7 位科学家平均估算 20 轮循环 ≈ 人类 6 个月研究工作量
  • 声称有 7 项发现经外部专家用独立数据/方法验证：4 项原创 + 3 项复现

几项代表性发现

🫀 SOD2 与心肌纤维化：通过基因数据建模，为「血液中 SOD2（超氧化物歧化酶 2）越多、心脏疤痕越少」提供人群基因组学层面的新证据，把小鼠实验结论往临床应用推进一步。

🧠 阿尔茨海默病新线索：发现随年龄增长，内嗅皮层神经元的磷脂翻转酶基因表达下降，且在人类患者数据中得到验证，与 tau 蛋白病理出现时间同步。

☀️ 钙钛矿太阳能电池：精准找到失效阈值——该结论来自其训练数据截止之后发表的论文，等于「闭卷考试」式复现。

🧬 低温小鼠大脑：独立验证一份未发表手稿的结论（核苷酸代谢是关键通路），且该预印本在其完成分析后才发布。

商业化：Kosmos 单次运行定价 200 积分（约 $200）；学术用户每月 650 积分免费；订阅 $200/月；常规 Agent（Analysis / Literature 等）对订阅用户免费。这也是「免费基础层 + 付费高吞吐」模式的落地。

3.4 实践案例

  • Incyte 战略合作（2026-05-19）：美国生物制药公司 Incyte 将 Kosmos 嵌入药物研发全流程，初期聚焦靶点发现与验证、转化生物学，用实验/临床/生物标志物数据支持决策；双方的理念是让药企数据变成「复利资产」——数据不再只是被分析，而是持续喂养 AI、形成反馈闭环，提升未来项目决策质量
  • Robin → dAMD 眼病新药：Nature 论文验证的完整科研闭环（见 3.2）
  • PaperQA 开源：Edison 在融资公告同日发布 PaperQA 2.0——旗舰开源文献智能体，延续「开源科学」承诺
  • 学术生态：Fellowship 项目向生物/生化领域学者开放 Kosmos 与 AI-for-Science 社区实践

小结：FutureHouse / Edison 的实践案例不是「流程自动化」，而是科学发现本身——从 Nature 论文到药企研发管线，衡量标准是「是否发现并验证了新东西」。

3.5 质疑与局限

科学界对 Kosmos 的反应并非一边倒喝彩，New Scientist 报道了相当尖锐的批评：

⚠️ 布里斯托大学 Fergus Hamilton：SOD2「发现」算不上首创（小鼠中已知），人群层面的因果推断存在方法学瑕疵；Kosmos 尝试运行的部分分析代码直接失败、被系统忽略，且数据被过度预处理——「可能只完成了任务的 10%」。帝国理工 Ben Glocker 提醒：应谨慎对待 AI 科学家的「自主使用」，其失败模式还不清楚。Bentley 大学 Noah Giansiracusa 则强调：科学不止数据驱动，还有深度思考与创造力。

Edison 自己也承认局限：约 30% 的运行会陷入局部最优解（盯着小发现不放）；跨领域问题准确率约 58%；官方建议关键课题并行运行 3-5 次交叉验证。Rodriques 的回应也值得记录：「我很接受部分发现可能是错的或被证伪——这正是科学。它引发如此成熟的批评，反而说明系统的力量。」他把 Kosmos 定位为协作者而非替代者。

五、观察与思考

① 殊途同归，但分工不同

两者都把「多智能体」当作下一代 AI 的形态，但 CrewAI 把 Agent 当作可编排的软件组件，任何流程都能装配；FutureHouse 把 Agent 当作科研流程的执行者，围绕「假设 → 实验 → 分析 → 验证」构建领域闭环。前者赢在通用性，后者赢在纵深。

② 两者其实可以互相借鉴

  • 用 CrewAI 编排科研 Agent 团队（文献 → 分析 → 写报告）在社区里已经有人做——「AI 科学家」也可以用通用框架搭出来；
  • Kosmos 的「全溯源」理念（每个结论对应代码或原文）恰恰是企业在 Agent 生产中最大的信任缺口，值得所有 Agent 平台学习；
  • 而 Kosmos 的「结构化世界模型」在长上下文聚焦上的经验，对任何多智能体系统都有参考价值。

③ 「人类在环」都是关键变量

CrewAI 的 Andy 案例：从 100% 人工审核降到 50% 自主，信任是挣来的；Kosmos 官方建议关键课题并行跑 3-5 次交叉验证，Rodriques 也强调「你仍然要亲自读、亲自验证」。两个系统在「自主」的表象下，都把人类当作最终裁判——这可能是 2026 年所有 Agent 系统的共同底线。

④ 未来走向

CrewAI 正在从「建 Agent 的框架」走向「告诉你建什么、并帮你管到生产」的发现引擎；FutureHouse/Edison 正在从「复现与延伸」走向「原创发现与临床转化」。当平台获得领域纵深、科研系统获得通用编排能力时，两条路会越来越近。

最后借用 New Scientist 报道里的一句话收尾：「科学不止是数据驱动的方法，还有深度思考与创造力——不应该因为我们可以自动化的那部分科学更适合 AI，就忽视另一部分。」
